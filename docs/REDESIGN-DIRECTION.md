## 产品方向

应用分为 Hermes Admin 与 Hermes 工作界面两个入口。
Admin 承担 NAS 生命周期、工作区入口和模型、工具、MCP、通讯、定时任务的配置管理；工作界面承担对话、会话和任务过程展示。
这些功能均以 Hermes 原生能力、原生配置和原生数据为基础。管理界面的归属与底层功能的实现分别考虑。
保持官方核心与官方界面的来源清晰，飞牛适配放在宿主层。

## 两个入口

| 入口 | 用途 | 建议路径 |
| --- | --- | --- |
| Hermes Admin | 生命周期、工作区入口，以及模型、工具、MCP、通讯、定时任务的统一管理 | `/app/hermes-agent/` |
| Hermes | 在浏览器中使用官方 Windows 桌面端同款工作界面 | `/app/hermes-agent/web/` |

Admin 概览页有“进入 Hermes”主按钮；第二个桌面图标直接打开工作界面。
后端代理统一处理子路径、静态资源、HTTP、WebSocket 与认证，前端不拼接内部端口。
服务未启动时，工作入口显示真实状态及返回 Admin 的操作。

### 已确定：桌面端界面的浏览器适配

当前固定的官方 0.22.2 中，浏览器 Dashboard 与 Windows Desktop 是两个产品前端：

- `app/hermes-src/web`：官方浏览器 Dashboard，聊天嵌入原生 TUI。
- `app/hermes-src/apps/desktop`：Electron + React，拥有独立聊天界面，依赖 `window.hermesDesktop` 等宿主桥接。
- 两者共用部分后端协议，但不能通过修改入口地址就互相替代。

采用桌面端界面的浏览器适配。复用官方 Desktop 渲染器与 JSON-RPC/HTTP 后端协议，增加独立的浏览器宿主层。文件选择、窗口、下载等桌面能力分别替换为浏览器或 NAS 能力。

官方浏览器 Dashboard 不作为第二入口的替代品。也不将桌面渲染器静态文件直接交给 Dashboard 托管而忽略 Electron 桥接。

供应商、工具、MCP、通讯和定时任务的完整管理入口统一放在 Admin；工作界面相关入口在宿主适配层跳转到 Admin 的对应页面。
工作界面仍保留日常操作，例如从已配置的模型中选择当前会话模型；这不构成另一套供应商/API Key 管理。
工作界面与 Admin 共享同一 profile 与会话归属，不复制会话数据库。

## Admin 页面建议

建议侧栏：概览、工作区、模型管理、工具、MCP、通讯、定时任务、运行日志、应用设置。
备份与恢复放入应用设置的维护分组，首版不增加独立侧栏页；工具与 MCP 可在视觉上分组，但配置职责保持明确。
管理页采用参考项目的视觉与交互，不因底层复用官方能力而嵌入整套官方 Dashboard。

### 概览

采用参考项目的主要布局：

1. 顶部标题与版本信息。
2. 应用主卡片，右侧“进入 Hermes”。
3. 状态网格：Gateway、官方界面服务、运行时间、CPU、内存。
4. 运行控制：启动、停止、重启、检查更新。
5. 部署、更新或故障时显示操作进度和可定位的错误。

应用包版本与核心版本分别展示。PID、端口、提交等诊断信息折叠显示。
依赖修复放到维护操作中；不把清空数据或恢复出厂设置作为首屏操作。

### 工作区

采用参考项目的工作区页布局与主要操作：

- 页头展示“工作区”和数量，右侧提供“数据目录”按钮。
- 桌面端双列卡片、移动端单列；卡片展示名称、NAS 目录路径、关联会话数，以及可获取的创建/更新时间。
- 点击工作区卡片，在飞牛文件管理器中定位对应目录；“数据目录”按钮定位应用数据目录。
- 从 Hermes 的原生项目/工作目录与会话信息生成列表，随原生数据更新，不另外维护一套工作区注册表。
- 无工作区时展示空状态，并引导用户在 Hermes 工作界面创建或选择项目/工作目录。

工作区目录代表 NAS 上的真实路径。普通浏览器无法调用飞牛文件管理 SDK 时，提供复制路径与进入飞牛桌面的提示。
工作区与原生项目、会话的具体字段映射在接口接入时核对；缺失的时间或统计显示为不可用，不填充虚构值。
首版范围对齐参考项目的列表和目录定位，不额外加入文件编辑器、删除目录或独立会话管理。

### 模型管理

供应商与自定义端点、凭据配置和验证、模型发现、默认模型及官方支持的辅助模型设置。
使用官方配置与验证接口，不再维护旧控制台的 providers-state 和独立聊天模型配置。

### 工具

展示官方工具集，支持启停、依赖/凭据配置与官方提供的工具参数。
保留 Hermes 官方工具能力；不恢复旧版业务连接器、评测与模型冒烟等额外产品模块。
技能和插件放在工具页的独立标签中，复用官方来源与管理能力。

### MCP

官方支持的服务添加、修改、启停、连通测试与授权。凭据由官方后端管理，OAuth 回调由宿主代理正确转发。

### 通讯

以官方平台目录生成配置页，支持平台启停、凭据、测试与官方提供的配对流程。
只承诺已接通并验证的平台，不凭静态平台名称宣称所有扫码与字段均可用。

### 定时任务

使用官方任务存储与调度器，提供新建、编辑、暂停、恢复、立即执行和执行记录。
任务按 profile 归属展示；工作界面可查看任务执行会话，完整任务管理进入 Admin。

### 运行日志

管理器、Gateway、界面服务三个来源；实时日志、搜索、自动滚动与下载。
展示诊断所需信息，不在日志中回显密钥。

### 备份与恢复（建议保留）

提供更新前的应用数据备份、恢复及备份时间/核心版本标识。
与 Hermes 的代码检查点区分：此处保护 NAS 应用配置与持久数据。
SQLite 使用一致性备份或在服务停止后备份；具体策略在实现时确定。

| 分组 | 首版建议包含 | 建议默认行为 |
| --- | --- | --- |
| 运行设置 | 应用启动后恢复服务、异常自动重启、重启重试上限 | 恢复上次状态；异常重启有次数上限，手动停止不触发自愈 |
| 访问设置 | 进入 Hermes 的打开方式（飞牛窗口/浏览器新标签）、访问方式（飞牛网关/独立端口/自定义地址）、独立访问端口、独立访问密码 | 优先飞牛网关；独立端口按需启用，内部监听端口折叠到高级项 |
| 网络与依赖源 | HTTP/SOCKS 代理、代理用途、Python/npm 安装源、连接测试 | 明确区分安装下载与模型/工具出站请求；保留依赖版本锁定 |
| 数据与日志 | 数据目录与缓存目录显示、文件管理定位、日志保留天数/空间上限 | 目录首版只读；日志轮转不删除会话、记忆或用户文件 |

| 维护与恢复 | 检查运行环境、修复依赖、重新部署当前固定版本、重置 Admin 设置、诊断信息导出；数据备份恢复入口 | 放在设置内；维护操作独立执行，不与表单保存混在一起 |
| 高级设置（已确认） | Hermes 原生上下文压缩、记忆、执行审批等高级参数 | 默认折叠，按 profile 读取与保存；保持官方默认值和生效规则 |
| 关于 | 应用包/核心版本、官方提交、Python/Node 版本、项目与发行说明链接 | 分别标明应用包和核心版本；数据来自实际运行环境 |

#### 运行设置的行为

飞牛应用中心控制整个应用是否开机启动；Admin 中的“恢复服务”控制管理器启动后是否拉起 Hermes 进程，两者在文案中区分。
建议默认恢复上次状态：用户手动停止的服务，在下次启动管理器时不擅自恢复。
后台任务/消息网关与对话管理后端的具体启停策略单独确认后，再确定是否展示分别恢复的选项。

#### 访问设置的行为

“打开方式”是飞牛窗口还是新标签；“访问方式”是网关、独立端口还是自定义地址，两者分别配置。
自定义地址是用户已配置好的反向代理地址，不承担创建域名、签发证书或运行隧道的功能。
飞牛网关沿用宿主访问权限；独立访问密码用于启用的独立 HTTP 入口，Admin 与工作界面执行一致的访问控制。
内部端口等高级参数只在需要排查冲突时展示，避免要求普通用户理解全部进程端口。

#### 网络设置的行为

代理用途明确区分“安装与组件下载”和“Hermes 出站请求”，展示实际作用范围。
本机与 NAS 内网接口不因启用下载代理而被错误转发。
安装源只改变下载位置，不能将固定依赖版本变为随源更新。
模型供应商端点、MCP 服务地址和通讯平台凭据在各自管理页面配置。

#### 维护操作的范围

- 检查环境：展示 Python、Node、核心文件、目录权限、端口和必要依赖的实际检测结果。
- 修复依赖：针对当前固定核心版本补齐/修复环境，保留配置和用户数据。
- 重新部署：重新安装当前固定版本的程序与构建产物，不在 NAS 上要求用户现场编译桌面前端。
- 重置 Admin 设置：仅恢复管理器的偏好与宿主设置，不重置 Hermes 配置、平台绑定和历史会话。
- 导出诊断：导出版本、状态与必要日志，过滤凭据。
- 数据备份与恢复：放入维护分组；优先复用原生能力，补齐 NAS 宿主设置范围与恢复验证。

“清空全部数据/恢复出厂设置”不建议加入首版；Node 堆内存上限不作为 Hermes 整体内存限制展示。
模型、工具、MCP、通讯、定时任务的业务配置分别在 Admin 对应页面管理，不重复放进应用设置。
其他 Agent 参数按同一高级设置原则逐项核对官方支持后纳入，不增加无对应原生能力的开关。

#### 高级设置（已确认）

默认折叠，展开后分为“上下文与压缩”“记忆”“执行与审批”等小组。
字段、可选值和默认值以当前固定 Hermes 版本的原生配置为准，不另建一套执行或记忆机制。
不提供旧版定制记忆蒸馏、知识镜像和危险命令正则等扩展的恢复入口。

高级参数按 profile 生效，页头明确显示当前编辑对象；NAS 访问端口、主题等宿主设置不随 profile 切换。
保存通过官方配置接口完成，保留未编辑字段，不覆盖整个配置文件。
区分立即生效、下个会话生效和需要重启；不为了设置即时生效而重写进行中会话的提示词、工具清单或历史。
工作界面的对应全局配置入口跳转到 Admin；会话内临时模型选择、工具执行审批等当次交互继续留在工作界面。
“恢复默认”只恢复选中的高级参数分组，不清空记忆内容、会话记录、凭据或其他 profile 配置。

#### 保存与生效反馈

只有字段发生修改时启用保存和取消；表单加载失败时禁止用空值覆盖已有配置。
保存前校验端口、地址和必填项；敏感输入区分“不修改”“替换”和“清除”，不把遮罩占位写回配置。
保存后列出立即生效与需要重启的项目，用户手动点击“应用并重启”才执行重启。
修复、重新部署等维护动作独立展示范围、状态和结果。

## 原生接口与数据边界

已在本地官方 0.22.2 源码中确认以下路由；这是代码核对，尚未完成新 Admin 的端到端接入验证。

| Admin 管理功能 | 官方接口示例 | 官方实现位置 |
| --- | --- | --- |
| 模型与供应商 | `/api/model/info`、`/api/model/options`、`/api/model/set`、`/api/providers/custom-endpoints`、`/api/providers/validate` | `hermes_cli/web_routers/models.py`、`config_env.py` |
| 工具集 | `/api/tools/toolsets`、`/api/tools/toolsets/{name}` | `hermes_cli/web_routers/tools.py` |
| MCP | `/api/mcp/servers`、服务测试/启停/授权相关路由 | `hermes_cli/web_routers/mcp.py` |
| 通讯 | `/api/messaging/platforms`、平台测试及 onboarding 相关路由 | `hermes_cli/web_routers/messaging.py` |
| 定时任务 | `/api/cron/jobs`、任务 pause/resume/trigger/runs 相关路由 | `hermes_cli/web_routers/cron.py` |

Admin 通过宿主代理调用原生管理接口，工作界面通过浏览器宿主桥调用相同后端的会话协议。
读取、保存和验证均使用同一 profile；不把所有配置默认写到主 profile。
保存后的状态从官方后端刷新；如需重启或只对新会话生效，界面显示实际生效范围。
认证、敏感值遮罩和浏览器会话由宿主与官方后端各自承担明确职责，不把服务端管理令牌公开到所有浏览器页面。

“移除”指产品入口和运行逻辑退出新版本，不等于删除用户文件、卸载官方技能或清空原生配置。

## 方案边界复核（已确认推进）

结论：两个入口的划分合理。优先补齐官方能力的管理入口和运行保障，保持现有侧栏规模，不再扩展自定义 Agent 产品功能。用户已同意按此边界继续推进；现阶段先验证新入口，旧功能按迁移原则逐项退出。

### 建议补齐的原生能力

| 能力 | 建议位置 | 首版范围与边界 |
| --- | --- | --- |
| 技能与插件 | 工具页下的“工具集 / 技能 / 插件”标签 | 技能使用官方来源、安装、更新、启停与检查；插件按固定版本实际支持的安装及配置接口接入，不重建聚合市场。插件业务页面仍由插件或工作界面承载。 |
| Profile 管理 | Admin 页头选择器；应用设置内管理 | 首版至少正确选择并显示当前 profile；创建、重命名、导入导出可在管理抽屉中提供。profile 是 Hermes 配置与数据隔离单位，不作为飞牛账号或权限隔离机制。 |
| 角色提示词与原生记忆 | 应用设置 → 高级设置 | 提供原生角色提示词（SOUL）编辑、记忆参数及文件定位；尊重工作区 AGENTS 的归属，不强制注入。是否直接编辑记忆内容需单独核对官方接口；不增加知识图谱和蒸馏系统。 |
| 原生语音 | 应用设置 → 高级设置 → 语音 | 管理官方 STT/TTS 等配置；录音、播放和实时交互留在工作界面。浏览器麦克风安全上下文、授权与 NAS 音频依赖需要验证；未通过验证的模式明确显示不可用。 |
| 备份、恢复与诊断 | 应用设置 → 维护 | 首版应具备可验证的备份和恢复路径。优先复用官方备份、导入及 doctor；区分 profile 导出与完整数据备份，另补宿主设置，不宣称二者等价。明确数据库一致性、凭据包含范围与恢复目标，恢复前校验并保留现有数据。暂不增加独立侧栏页。 |
| 供应商登录与辅助模型 | 现有模型管理 | 除 API Key 和自定义地址，还应接入固定版本实际支持的登录/授权方式及辅助模型配置；不强行把所有供应商简化为同一种密钥表单。 |

这些能力已在本地固定版本源码中找到对应实现或配置，接口是否可直接用于 NAS 浏览器仍需接入验证。语音和插件等宿主相关能力逐项标注支持状态，避免仅凭页面存在就宣称可用。

建议将技能管理、profile 正确作用域、备份恢复及环境诊断纳入首版；完整插件管理和语音浏览器适配按验证结果安排。未移植管理入口时保留原生数据与配置，不把未完成接入解释为删除该能力。

### 两个入口的职责细化

| 场景 | Hermes Admin | Hermes 工作界面 |
| --- | --- | --- |
| 模型 | 供应商、授权、默认与辅助模型 | 当前会话选择模型 |
| 工具与安全 | 工具可用性、技能/插件、MCP、长期审批策略 | 本次工具执行审批、调用结果与委派进度 |
| 角色与记忆 | profile、持久角色提示词、原生记忆参数 | 会话中的原生记忆交互与上下文操作 |
| 工作区 | 目录索引、关联信息、飞牛文件管理入口 | 选定项目开展工作、附件和产物预览 |
| 定时任务 | 创建、修改、启停、手动触发及执行记录 | 打开执行产生的会话与结果 |
| 外观与语音 | Admin 外观、宿主访问方式、语音供应商配置 | 工作界面外观、录音、播放与会话交互偏好 |

所有持久业务配置和数据沿用官方存储；Admin 只保存自身宿主配置。浏览器选择 profile 时按请求传递作用域，不为了切换页面而修改全局活动 profile，避免两个浏览器互相影响。

### 生命周期与浏览器适配的实施门槛

- 概览分别显示 Admin、原生 API/工作服务、通讯 Gateway 的实际状态。建议提供“停止通讯网关”和“停止全部 Hermes 服务”，后者保持 Admin 可访问；配置依赖的服务停止后，提示需要启动，不擅自恢复。
- 先完成桌面渲染器的最小浏览器适配验证：连接鉴权、流式对话、中止、会话恢复、profile 作用域、文件上传下载和飞牛子路径下的 WebSocket。通过后再全面替换旧控制台。
- “同款界面”要求复用官方渲染器与交互；文件实际位于 NAS。Electron 的本机窗口、自动更新、系统快捷键等能力分别适配，不承诺直接在浏览器复现所有 Windows 系统集成。
- 首版不再增加自定义工作流、专家团队、知识库平台、模型部署中心或独立统计系统；官方原生委派、插件和会话能力继续保留。

## 视觉与技术建议

- 管理页采用参考项目的 Vue 3 + TypeScript + Naive UI + Pinia + Vite 结构。
- 延续 240px 桌面侧栏、浅灰背景、白色 16px 圆角卡片、蓝色主操作、浅蓝选中态。
- 保留深色主题、跟随飞牛主题与移动端布局。
- 不复制参考项目的 DeepSeek 品牌、插件操作或 DSH 特定代理补丁。
- 第一阶段重做 Admin 前端与接口边界，后端按需提取现有 Node 管理能力，不同时强制重写为 Go。
- 工作界面复用官方 Desktop 的视觉和会话交互；Admin 的设计统一参考 Harness Admin。
- 桌面端浏览器适配放在独立宿主/构建层，不继续沿用旧自定义聊天协议，也不将官方 Desktop 改造成另一个手写聊天前端。

## 生命周期边界

- 停止 Hermes：Gateway/工作界面服务停止，Admin 仍可访问日志与启动操作。
- 在飞牛应用中心停止应用：整个管理服务停止。
- Gateway 与官方界面服务分别报告状态；其中一个可用时不将整体显示为全部健康。
- Admin 本身可访问与原生管理接口可用分别报告；原生服务停止后，需要该服务的配置页明确提示状态，不把请求失败显示为默认空配置。
- 是否始终保留原生管理后端，以及“停止全部服务”和“停止消息网关”的具体操作区分，在生命周期实现方案中明确；不后台悄悄重启用户已停止的服务。
- 更新依次完成备份、停止服务、应用版本、依赖准备、健康确认；失败有明确日志和恢复路径。
- 首版继续通过 FPK 更新核心；独立在线升级若有需要，单独制定与 FPK 的版本所有权规则。

## 迁移原则

1. 保留当前 0.21.150 安装包、源码备份及数据备份。
2. 先验证官方桌面渲染器的浏览器宿主适配；新 Admin 独立构建，验证两个入口与生命周期后替换旧控制台。
3. 停用旧功能的自动写入、自动镜像、重复配置同步与后台任务，再清理相关代码。
4. `.env`、config.yaml、profiles、官方数据库、技能与用户提示词保持原始归属。
5. 旧控制台 JSON 会话、房间、工作流和知识库文件先归档或提供导出；不直接宣称已迁移为官方会话。
6. 用户自定义 SOUL/AGENTS 不覆盖；旧版本内置的冗长知识注入与可选技能安装策略另行确认。
